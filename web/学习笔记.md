### 🚀 插件配置：让 Vite 更强大

配置文件的核心是 `plugins` 数组，它通过“插件”机制为 Vite 扩展了丰富的功能。

```javascript
plugins: [
    vue(),                           // 1. Vue 3 单文件组件支持
    AutoImport({                     // 2. 自动导入 API
        resolvers: [ElementPlusResolver()],
    }),
    Components({                     // 3. 自动注册组件
        resolvers: [ElementPlusResolver()],
    }),
],
```

| 插件 | 功能 | 带来的好处 |
| :--- | :--- | :--- |
| **`vue()`** | **Vue 3 核心插件** | 这是让 Vite 能够理解和处理 `.vue` 文件的必备插件，是所有 Vue 项目的基础。 |
| **`AutoImport`** | **API 自动导入** | 可以让你直接使用 `ref`、`computed`、`watch` 等 Vue Composition API，而无需在每个文件中手动写 `import { ref } from 'vue'`。 |
| **`Components`** | **组件自动注册** | 让你在模板中直接使用 `<ElButton />`，而无需在 `<script>` 里手动导入和注册。 |
| **`ElementPlusResolver`** | **Element Plus 组件解析器** | 这是为上面两个插件提供的“解析规则”，告诉它们如何按需引入 Element Plus 组件。这是实现**按需加载**的关键，能有效减小打包后的文件体积。 |

### 📂 路径解析：告别繁琐的相对路径

`resolve` 配置项用于设置模块的解析规则，让你能更方便地导入文件。

```javascript
resolve: {
    alias: {
        '@': fileURLToPath(new URL('./src', import.meta.url))
    },
},
```

*   **`alias` (别名)**：这里定义了一个 `@` 符号，指向项目根目录下的 `./src` 文件夹。
*   **带来的好处**：你现在可以使用 `import myComponent from '@/components/MyComponent.vue'` 来代替像 `../../../components/MyComponent.vue` 这样冗长且难以维护的相对路径，无论文件嵌套多深，`@` 始终指向 `src` 目录，让代码更清晰。

1.  **开发时**：通过自动导入和路径别名，减少重复的样板代码，让你更专注于业务逻辑。
2.  **构建时**：通过 `ElementPlusResolver` 实现按需加载，只打包使用到的组件，让最终生成的网站加载更快。

### 🚀 创建 Axios 实例

```typescript
const service = axios.create({
    baseURL: 'http://127.0.0.1:8080/api',
    timeout: 10000,
})
```

*   **`baseURL`**: 设置了所有请求的基础路径。这样，在业务代码中请求 `/login` 时，实际请求的完整 URL 就是 `http://127.0.0.1:8080/api/login`。这不仅方便统一修改，也减少了重复代码。

### 📦 定义响应数据结构

```typescript
export interface ApiResponse<T> {
    code: number;
    msg: string;
    data: T;
}
```

这段代码定义了一个**通用的 TypeScript 接口（Interface）**，用于描述后端返回的统一数据格式。

*   `code`: 业务状态码（如 `0` 表示成功，非 `0` 表示失败）。
*   `msg`: 提示信息。
*   `data`: 实际的业务数据，其类型由泛型 `T` 决定。

**好处**：在业务代码中调用接口时，可以这样使用 `const res = await api.login(data);`，TypeScript 能准确地推断出 `res.data` 的类型，提供智能提示和类型检查。

### 🛠️ 配置请求拦截器

```typescript
service.interceptors.request.use(
    (config: AxiosRequestConfig) => {
        config.headers = {
            'Content-Type': 'application/json',
            ...config.headers,
        }
        return config as InternalAxiosRequestConfig
    }
)
```

**请求拦截器**会在每个请求**发送之前**执行，用于对请求配置进行统一处理。

*   **统一设置请求头**: 为每个请求添加 `Content-Type: application/json`，表示请求体以 JSON 格式发送。
*   **保留自定义请求头**: 使用展开运算符 `...config.headers` 确保调用者传递的自定义请求头（如 `Authorization`）不会被覆盖。
*   **类型断言**: `as InternalAxiosRequestConfig` 是告诉 TypeScript 这个配置已经符合内部要求的类型，这是一种标准的类型处理写法。

> **🚧 注意**: 目前这个配置中**没有添加认证 Token**。在实际项目中，通常在这里从 `localStorage` 或 Pinia Store 中获取 Token，并添加到 `headers` 中（如 `Authorization: Bearer <token>`）。

### 🎯 配置响应拦截器

```typescript
service.interceptors.response.use(
    (response: AxiosResponse) => {
        return response.data
    }
)
```

**响应拦截器**会在所有响应**返回业务代码之前**执行，用于对后端返回的原始数据进行预处理。

*   **简化数据访问**: 它的作用是直接返回 `response.data`。这样，业务代码中调用 `api.login(data)` 获取到的结果，就是后端返回的数据主体（即 `ApiResponse<T>` 结构），而不用再多写一层 `.data`。

2.  **完整的类型注解**: 每个函数都明确标注了**参数类型**和**返回值类型**。例如 `userList` 接收 `UserListRequest` 类型参数，返回一个 `Promise<ApiResponse<PageResult<User>>>`。这意味着调用方可以明确知道它需要什么数据，以及成功后会得到什么结构的数据。
3.  **统一的响应格式**: 所有接口返回的 Promise 都被 `ApiResponse<T>` 包裹，与后端 `response` 包中定义的统一格式遥相呼应。

#### 3. 关键业务逻辑映射

*   **注册 (`register`)**: 注意它返回的是 `LoginResponse`，这意味着后端在注册成功后，会直接返回用户信息和访问令牌，前端可以据此实现“注册即登录”的流畅体验。
*   **用户列表 (`userList`)**: 它接收 `UserListRequest` (继承自 `PageInfo`) 并返回 `PageResult<User>`，完美对接了后端的**分页查询**功能，并支持按 `uuid` 和 `register` 字段进行筛选。
*   **用户冻结/解冻 (`userFreeze`/`userUnfreeze`)**: 这两个操作是管理后台的核心功能，对应了后端 `UserFreeze` 和 `UserUnfreeze` 的 API，实现了对用户状态的管控。

### 🚀 动态标题脚本解析

页面标题的独特之处在于，它通过一段内联 JavaScript 从后端 API 获取，而不是硬编码在 HTML 中。

```html
<script>
    fetch('/api/website/title')           // 1. 请求后端 API
        .then(response => response.json()) // 2. 解析 JSON 响应
        .then(data => {
            document.title = data.title   // 3. 设置页面标题
        })
</script>
```

**执行流程**：
1.  **请求后端**: 浏览器加载页面时，会向 `/api/website/title` 这个接口发送一个 GET 请求。
2.  **获取数据**: 后端接口返回一个 JSON 对象，例如 `{ "title": "我的个人博客" }`。
3.  **更新标题**: JavaScript 代码提取 `data.title` 的值，并将其赋给 `document.title`，从而动态修改了浏览器标签页上显示的标题。

---

### 💎 设计优势

这种动态获取标题的方式，相比于在 HTML 中写死 `<title>` 标签，有几个明显的优点：

1.  **内容与代码分离**: 网站标题、图标等配置信息存储在数据库中，由后端 API 提供。这样，运营或管理员可以通过后台管理系统（如网站设置页面）轻松修改标题，而无需改动前端代码或重新部署项目。
2.  **统一配置中心**: 标题和图标都通过 `/api/website/` 下的接口获取，这与后端 `model/other` 中定义的网站配置结构是相对应的，形成了一个完整的配置管理闭环。
3.  **SEO 友好**: 虽然页面标题是动态设置的，但它是通过服务器端渲染（SSR）或客户端渲染（CSR）在页面加载的早期阶段完成的。搜索引擎爬虫在抓取页面时，通常能够正确读取由 JavaScript 设置的 `document.title`，因此这不会对 SEO 产生负面影响。

### ⚠️ 使用提示

需要注意的是，这个脚本位于 `main.ts` 加载**之前**执行，并且在逻辑上独立于 Vue 应用。这种做法的好处是页面标题可以尽早确定，但如果你想在 Vue 组件内部获取或修改标题（例如，在路由切换时动态更新页面标题），你可能还需要在 Vue Router 的 `afterEach` 钩子中做一些补充处理。

### 🧩 模板结构解析

模板部分非常简洁，构建了一个清晰的页面结构：

```vue
<template>
  <div class="web">
    <el-container>
      <!-- 核心内容区域 -->
      <router-view/>
      <!-- 页脚部分 -->
      <el-footer>
        <web-footer/>
      </el-footer>
    </el-container>
  </div>
</template>
```

`el-container` 是 Element Plus 的布局容器组件，用于搭建页面的基础框架。它只包含了 `router-view` 和 `el-footer` 两个部分。

*   **`<router-view/>`**: 这是 Vue Router 的**路由出口**。它就像一个占位符，告诉 Vue 应该在这里渲染当前路径匹配到的页面组件。例如，当用户访问 `/` 时，这里会渲染 `Home.vue`；访问 `/about` 时，会渲染 `About.vue`。
*   **`<el-footer>`**: 这是 Element Plus 的页脚组件，它包裹了自定义的 `WebFooter` 组件。这确保了网站的页脚在所有页面中保持一致。

### 💎 与后端架构的关联

这个前端布局组件与后端的 `router` 层设计相呼应，共同构成了完整的 MVC 模式：
